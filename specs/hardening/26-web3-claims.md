## 3. Hook Capabilities & Passive Telemetry Scope

An audit of [`contracts/src/DarkTraceHook.sol`](file:///c:/Users/user/Desktop/darktrace/contracts/src/DarkTraceHook.sol) establishes the following hard technical boundaries:

1. **Non-Blocking Telemetry:**  
   The hook does **not** revert, block, delay, or modify swap executions. In both `beforeSwap` and `afterSwap`, it returns standard zero deltas:
   ```solidity
   return (IHooks.beforeSwap.selector, BeforeSwapDeltaLibrary.ZERO_DELTA, 0);
   return (IHooks.afterSwap.selector, 0);
   ```
2. **EIP-1153 Transient Storage Scope & Cross-Tx Fallback:**  
   Standard `tstore` / `tload` clears at the end of each EVM transaction. To track sandwiches executed across 3 separate transactions in the same block, `DarkTraceHook` writes to `sstore` fallback slots alongside `tstore`:
   ```solidity
   assembly {
       valA := tload(slotA)
       if iszero(valA) { valA := sload(slotA) }
   }
   ```
   State resets automatically when `s.lastBlock != block.number`.
3. **Sender Semantics in Uniswap v4:**  
   The `sender` argument in `afterSwap(address sender, ...)` is the immediate caller of `poolManager.swap(...)`. In standard DeFi interactions, this is the Router (e.g. Universal Router) rather than the user's EOA. The hook tags this caller; end-to-end user identity resolution is left to off-chain indexer analysis.
4. **No Cross-Chain Execution in Hook:**  
   The hook operates strictly on Base Sepolia. It has no bridge hooks, cross-chain messaging primitives, or Arc settlement capabilities.
