## 1. Architectural Distinction of Identifiers

Through rigorous on-chain and code audits, the DarkTrace identifier model has been formalized into four strictly separated concepts:

1. **`receiptHash` (`0x${string}`, 32 bytes / 64 hex chars)**:
   - **Origin:** Deterministically computed by `computeReceiptHash()` using `keccak256` over the canonical lexicographical JSON encoding of `ExtractionReceipt`.
   - **Role:** The primary application-layer receipt identifier. Used for Next.js routing (`/receipt/<receiptHash>`), Arc `SimulationRegistry.attest()`, and querying Arkiv via the indexed attribute:
     ```typescript
     client.select({...}).from(ReceiptsSchema).where(eq("receiptHash", hash))
     ```
2. **`arkivEntityKey` (`0x${string}`, 32 bytes / 64 hex chars)**:
   - **Origin:** Generated by the Arkiv Rabdi DB-chain upon processing the `createEntity` transaction.
   - **Role:** The ledger primary key (`$key`). Required for direct lookups on the Arkiv Block Explorer:
     ```
     https://rabdi.explorer.arkiv.network/entity/<arkivEntityKey>
     ```
   - **Crucial Rule:** Explorer entity URLs do **not** accept `receiptHash`. Querying `$key` with `receiptHash` returns 0 entities. Explorer links must strictly use `arkivEntityKey`.
3. **`arkivWriteTxHash` (`0x${string}`, 32 bytes / 64 hex chars)**:
   - **Origin:** The EVM transaction hash returned by `walletClient.createEntity()`.
   - **Role:** Immutable audit trail proving the on-chain write to Rabdi testnet (Chain ID `7794095`).
4. **`arkivURI` (`string`, URI format)**:
   - **Origin:** `arkiv://darktrace.v1/receipt/<receiptHash>`.
   - **Role:** Internal DarkTrace namespace reference. Clearly labeled as an internal schema URI rather than an external web link.
